ℹ️ How This Prevention System Works
1
Enter Transaction Features
Supply the graph-level properties of the Bitcoin transaction — its time step, wallet degree (connections), BTC volume, and any known risk signals like suspicious address connections or short wallet lifetime.
2
GNN Computes Fraud Score
The Spectral-Temporal GNN processes the transaction's graph neighborhood — the Spectral Filter removes adversarial noise, the GAT weighs suspicious edges, and the LSTM tracks temporal behavior across time steps. This produces a fraud probability score (0–100%).
3
Prevention Decision Is Applied
The score is compared to the trained thresholds from graph_decision() in training/train.py:
Score ≤ 50% → ✅ ALLOW 50% < Score ≤ 80% → ⚠️ Require OTP Score > 80% → 🚫 Block
4
Action Is Enforced Instantly
ALLOW — the transaction proceeds. OTP — an extra verification is triggered before funds move. BLOCK — the transaction is halted immediately and flagged for compliance review. The system prevents fraud before the transfer completes.

🔑 Key System Components
Spectral Filter models/spectral_filter.py
Normalised Laplacian smoothing suppresses high-frequency adversarial noise injected via fake edges. Prevents graph injection attacks from fooling the GAT.
GAT Encoder models/gat_encoder.py
Multi-head Graph Attention learns which transaction neighbors matter. Camouflage edges (fraud hiding among licit) get lower attention weights automatically.
Temporal LSTM models/temporal_lstm.py
Aggregates per-step embeddings into a sequence fed through an LSTM. Detects laundering chains (A→B→C→D) that only become suspicious over multiple time steps.
Adversarial Defence models/adversarial_injection.py
Training includes 1,000 synthetic fake nodes with 3 injected edges each, simulating camouflage attacks. The spectral filter is trained to be robust against these.
